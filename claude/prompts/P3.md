# P3 — Telegram 웹훅

```
목표: 텔레그램 메시지가 시트 원장에 기록되고 남은 한도가 회신된다.

읽을 파일: CLAUDE.md, docs/ARCHITECTURE.md, apps-script/src/{Config,Sheet,Parser,Classifier,Budget}.js 의
export 목록만 (구현 세부는 읽지 않는다).

작업:
1. `apps-script/src/Telegram.js`
   - `tg(method, payload)`: UrlFetchApp.fetch(`https://api.telegram.org/bot${getSecret('BOT_TOKEN')}/${method}`),
     muteHttpExceptions true, 실패 시 Log 탭에 기록.
   - `sendMessage(chatId, text, replyMarkup?)`, `editMessageText(...)`, `answerCallbackQuery(id, text?)`.
   - `setWebhook()`: 배포 URL 은 Script Properties `WEBAPP_URL` 에서 읽고
     `${WEBAPP_URL}?token=${WEBHOOK_SECRET}` 로 등록. `deleteWebhook()` 도 제공.
     주의: Apps Script doPost 는 요청 헤더를 읽을 수 없으므로 secret 은 반드시 URL 파라미터로 검증한다.
2. `apps-script/src/Webhook.js`
   - `doPost(e)`:
     a. `e.parameter.token !== getSecret('WEBHOOK_SECRET')` → 200 "ok" 반환 (아무것도 하지 않음).
     b. update 파싱. `message` 또는 `callback_query` 만 처리. 그 외 무시.
     c. 발신 user id 가 Config.allowed_telegram_ids 에 없으면 무시(회신도 하지 않음).
     d. 원문을 Log 탭에 먼저 기록.
     e. 메시지 → `handleMessage(chatId, userId, text)`, 콜백 → `handleCallback(cq)`.
     f. 항상 ContentService.createTextOutput('ok') 반환. 모든 예외는 try/catch 로 잡아 Log 에 남기고 200.
   - `handleMessage`:
     - parseMessage 결과 intent 별 분기.
     - record: classify 로 사전 조회. 매칭되면 Transactions 에 append (source telegram, status active,
       payer = Config 에서 userId→이름 매핑, 없으면 userId). Merchants.hit_count +1, last_used 갱신.
       매칭 행에 recurring_id 가 있으면 새 행 대신 이번 달 해당 recurring_id 의 status=expected 행을 찾아
       amount/amount_usd/date 를 덮어쓰고 status=confirmed (없으면 새 행 append, kind fixed).
       회신: 유동비면 formatStatusLine, 고정비면 "✓ 관리비 $212 확정 (예상 $207)".
     - 미매칭: Config.envelopes + ["고정비", "수입"] 을 inline 버튼으로 전송.
       콜백 데이터: `cls|<pendingKey>|<envelope>`. pending 파싱 결과는 CacheService 에 10분 저장
       (key = chatId:messageId).
     - confidence low: 기록은 하되 회신 끝에 "(확인 필요)" 와 `[삭제]` 버튼(`del|<txId>`).
     - query: Config.envelopes 각각 envelopeStatus 계산해 한 줄씩 회신. 고정비·부채·자산은 회신하지 않는다.
     - undo: 해당 userId 가 오늘 만든 마지막 active 행을 status=deleted 로. 없으면 "취소할 항목 없음".
     - unknown: 사용법 3줄 회신.
   - `handleCallback`: `cls|` → Merchants 에 행 추가(keyword = 원 merchantText 정규화 전 문자열) 후 기록·회신,
     `del|` → soft delete 후 메시지 편집. 항상 answerCallbackQuery.
3. `apps-script/src/Ledger.js`: `recordTransaction(parsed, cls, meta)` 와 `confirmRecurring(...)`,
   `softDelete(txId, by)`, `lastActiveByUser(userId, date)` — Webhook.js 는 이 함수들만 호출.
4. `docs/SETUP.md` 에 P3 절 추가: 배포(새 배포 → 웹 앱 → 실행: 나, 액세스: 모든 사용자) → 배포 URL 을
   Script Properties `WEBAPP_URL` 에 저장 → 편집기에서 `setWebhook` 실행 → 봇에 "코스트코 1.00" 전송해
   Transactions 와 Log 에 행이 생기는지 확인 → "취소" 로 삭제 확인.
5. `claude/prompts/P3.md` 저장, STATUS.md 갱신.

검증:
- `node --check apps-script/src/*.js` 통과, `npm test` 여전히 통과.
- `grep -n "getSecret('BOT_TOKEN')" apps-script/src/Telegram.js` 가 정확히 1곳 (토큰이 흩어지지 않음).
- `grep -rn "deleteRow\|clearContent" apps-script/src/` 결과가 비어 있음 (Golden Rule 3).
- doPost 의 첫 번째 검사가 token 비교인지 코드 인용으로 보고.

종료 조건: 커밋 "P3: Telegram 웹훅과 원장 기록" 후 멈춘다. 실제 배포·테스트는 사용자가 SETUP.md 로 진행.
```
