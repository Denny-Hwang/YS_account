# P10 — 웹앱 시각화 개편과 예상 수입

```
목표: 세로 목록 대신 그래프로 읽히게 한다. 예상 수입을 기록할 자리를 만든다.

작업:
1. 오늘: 봉투 합산 일일 가용액을 맨 위에. 봉투마다 예산 대비 집행을 불릿 막대(계획 진도 눈금 포함)로.
2. 예산: 봉투별 불릿 막대 + 누르면 편집.
3. 수입 탭 신설: 고정(급여) / 변동(레슨) 수입원을 등록하고 예상 대비 실제를 본다.
   저장은 Recurring 탭에 type=income 으로. 고정만 월별 예정 행을 만든다.
4. 더보기: 고정비(불릿 + 구성), 부채(원금 순위 + 상환 종료), 자산(추이 선 + 구성), 목표(진행 + 도달 예상).
5. 리포트: 수입/지출, 순저축(양음), 고정/유동(누적), 이달 누적 유동비 vs 계획선, 봉투별 6개월,
   카테고리(전월 대비), 많이 쓴 곳, 자산 전망. 표 보기 토글.
6. 봇: 사전에 없어도 Recurring 항목 이름이 들어 있으면 그 항목을 확정한다.

검증: apps-script npm test, node --check, webapp npm test + build, 실제 렌더링 스크린샷 8장.
```

## 구현 메모
- **차트 부품은 하나의 파일**(`components/Charts.tsx`)이고 라이브러리가 없다. Bullet, RankBars, MonthlyBars,
  DivergingBars, StackedBars, LineChart(SVG), SmallMultiples, Stat, Legend. 집계는 `lib/metrics.ts` 순수 함수다.
- **색은 역할로 고정**한다. 파랑 = 수입·자산, 주황 = 지출·부채, 회색 = 계획·기준, 빨강 = 초과.
  파랑·주황 조합은 P8 에서 dataviz 검증기를 통과했다. 봉투마다 다른 색을 주지 않았다.
  세 봉투에 세 색을 주면 같은 화면의 수입·지출 색과 뜻이 겹친다. 대신 작은 다중 차트로 나란히 비교한다.
- **계열이 둘 이상이면 범례**, 값은 항상 글자로도 적는다. 리포트에는 표 보기 토글이 있다.
- **불릿 막대**가 예산 대비 집행의 기본형이다. 트랙(목표)·채움(실제)·눈금(오늘까지의 계획)을 한 줄에 담는다.
  "오늘 눈금보다 덜 썼나" 를 한눈에 본다.
- **"실제" 는 active·confirmed 만** 센다(`isCounted`). expected 는 예정이라 리포트 합계에서 뺀다.
  이 규칙을 `metrics.ts` 한 곳에 두었다. 전에는 화면마다 `!== 'deleted'` 로 달랐다.
- **예상 수입**은 새 탭을 만들지 않고 Recurring 에 `type` 열을 붙였다. 예약·확정·월 마감 보고가 그대로 굴러간다.
  `kind=variable` 은 예정 행을 만들지 않고 카테고리로 실제를 묶는다. 레슨은 건별로 들어오기 때문이다.
- **Recurring 이름 매칭**: 봇이 사전에서 못 찾으면 active 항목 이름이 텍스트에 들어 있는지 본다.
  긴 이름이 우선이다. 사전에 없는 "급여", "자동차 보험" 도 확정된다.
- 하단 탭은 여섯 개다. 400px 에서 글자 12px 로 들어간다.
