# P2 — 파서·분류·예산 계산 (순수 모듈 + 테스트)

```
목표: Google 서비스 의존 없는 순수 JS 모듈 3개와 단위 테스트. 이 단계에서 GAS 호출 코드는 쓰지 않는다.

읽을 파일: CLAUDE.md, docs/ARCHITECTURE.md, docs/SHEET_SCHEMA.md.

작업:
1. `apps-script/src/Parser.js` — `parseMessage(text, ctx)` → 객체 또는 null.
   ctx = { today: 'YYYY-MM-DD', defaultCurrency: 'USD', fxUsdKrw: number }
   반환: { intent: 'record'|'query'|'undo'|'unknown', type, amount, currency, amount_usd,
           date, merchantText, memo, confidence: 'high'|'low' }
   규칙:
   - 금액: `(\d+(?:[.,]\d{1,2})?)` 와 접미/접두 표기. `85.89`, `$85.89`, `85불`, `5만원`, `50000원`,
     `₩50,000`, `12.5k`(불허, unknown). 원/₩/만원 → KRW. 만원은 ×10,000. 두 개 이상 금액이면 confidence low.
   - 날짜: `오늘`(기본), `어제`, `그제`, `9/8`, `09-08`, `2026-09-08`. 미래 날짜는 오늘로 강제하고 low.
   - 조회 의도: `얼마 남았어`, `남은`, `오늘`, `잔액`, `상태` 만 있고 금액 없음 → query.
   - 취소: `취소`, `undo` → undo.
   - 수입 힌트: `수입`, `급여`, `레슨`, `입금` 포함 → type income. 그 외 expense.
   - merchantText: 금액·날짜·힌트 토큰을 제거한 나머지를 공백 정리. 비어 있으면 low.
   - amount_usd: USD 면 amount, KRW 면 amount / fxUsdKrw 를 소수 둘째 자리 반올림.
   - 파일 끝: `if (typeof module !== 'undefined') module.exports = { parseMessage }`.
2. `apps-script/src/Classifier.js` — `classify(merchantText, merchants)` → 매칭 행 또는 null.
   merchants = Merchants 탭 객체 배열. 정규화: 소문자, 공백/특수문자 제거. 가장 긴 keyword 가
   merchantText 정규화 문자열에 포함되면 매칭. 동점이면 hit_count 큰 것.
   `normalize(s)` 도 export.
3. `apps-script/src/Budget.js` — 순수 계산.
   - `daysInMonth(yyyyMm)`, `remainingDaysInclToday(today)`.
   - `envelopeStatus({ budget, transactions, envelope, today })` →
     { budget, spentBeforeToday, spentToday, spentTotal, remaining, remainingDays,
       allowanceToday, plannedPaceToDate, deltaVsPlan }
     spent 는 status ∈ {active, confirmed} 이고 type=expense, kind=variable 인 행만, amount_usd 합.
     allowanceToday = (budget − spentBeforeToday) / remainingDays, 소수 둘째 자리.
     plannedPaceToDate = budget × (dayOfMonth / daysInMonth). deltaVsPlan = plannedPaceToDate − spentTotal.
   - `formatStatusLine(status, envelopeName)` → 한 줄 한국어 문자열
     예: "식료품 잔액 $771.30 · 남은 20일 × $38.57/일 · 계획 대비 +$135.20"
4. 테스트 `apps-script/tests/parser.test.js`, `classifier.test.js`, `budget.test.js`
   (`node:test`, `node:assert/strict`). 최소 케이스:
   parser: "코스트코 85.89" / "어제 세이프웨이 13.97" / "5만원 송금 부모님" / "레슨 윤지 40" /
           "얼마 남았어" / "취소" / "85.89 12.50 뭔가"(low) / "주유"(금액 없음 → unknown) / "9/8 주유 52"
   classifier: 대소문자, 공백, 부분일치, 최장 일치 우선, 미매칭 null.
   budget: 9/10, 예산 1000, 이전 지출 195.02, 오늘 0 → allowanceToday 38.33(21일 남음), 예산 초과 시 음수 허용,
           status=deleted 행 제외, kind=fixed 행 제외.
5. `claude/prompts/P2.md` 저장, STATUS.md 갱신.

검증: `cd apps-script && npm test` 전부 통과. 실패 케이스 있으면 코드 수정 후 재실행. 테스트를 약화시키지 않는다.
`grep -l "SpreadsheetApp\|UrlFetchApp\|PropertiesService" apps-script/src/Parser.js apps-script/src/Classifier.js apps-script/src/Budget.js`
결과가 비어 있어야 한다.

종료 조건: 테스트 통과 후 커밋 "P2: 파서·분류·예산 순수 모듈과 테스트" 하고 멈춘다.
```

## 구현 메모
- `package.json` 의 test 스크립트는 `node --test "tests/*.test.js"` 로 둔다. 이 환경의 Node 22 에서
  `node --test tests/` 는 디렉터리를 모듈로 해석해 실패한다.
- `parseMessage` 는 `merchantTextRaw`(금액·날짜만 제거) 필드를 추가로 돌려준다. 수입 힌트인 `레슨` 이
  Merchants 사전의 키워드이기도 해서, 힌트를 제거한 `merchantText` 로 미매칭일 때 Webhook 이
  `merchantTextRaw` 로 한 번 더 조회할 수 있게 하기 위함이다.
